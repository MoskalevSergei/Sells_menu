# Принятая методика и интерфейс

Этот файл фиксирует итоговые правила проекта, а не все промежуточные варианты обсуждения. Все числовые примеры в публичном проекте искусственные.

## Продажи и ассортимент

- Количество считается в штуках. Коэффициенты ПК не используются.
- В СПР 1 означает «Новое», 0 — «Сезонное». Тип меню в интерфейсе: Все / Новое / Сезонное.
- Для каждой новинки используется одна общая дата запуска из СПР.
- Запуски по ресторанам задаёт обязательный при новой загрузке лист «Рестораны_Блюдо». Его строки сопоставляются со СПР **строго по коду**, без сопоставления названий. Оценивается пересечение: блюдо есть в СПР и его пара блюдо/ресторан есть в списке запусков. Правило действует для новых и сезонных блюд во всех вкладках и трёх моделях рейтинга.
- Все коды СПР, включая блюда без продаж и будущие запуски, должны иметь хотя бы одну запись ресторана в «Рестораны_Блюдо». Отсутствие кода СПР в списке, пустой код СПР или незаполненная пара вызывают ошибку загрузки с пояснением. Текущие данные при ошибке не заменяются. Коды списка, отсутствующие в СПР, игнорируются как новинки. Повторные пары учитываются один раз; пробелы и регистр названий ресторанов не меняют сопоставление. Текстовые ведущие нули кодов сохраняются.
- Продажи блюда СПР в ресторане вне списка не входят в продажи запусков, их подходящую базу заказов, факт и охват рейтинга. В соответствующей группе эти продажи остаются обычным ассортиментом для весов и истории, включая даты до общей даты запуска этого блюда. Пояснение в дашборде показывает число пар и исключённых из запусков строк за все даты основного файла.
- Ассортимент определяется отдельно для блюда, разрешённого для запуска ресторана и нормализованного канала по всей загруженной истории. Хотя бы одна положительная продажа после запуска означает, что блюдо продаётся в этом сочетании. Само наличие пары в списке не означает, что ресторан продаёт блюдо во всех каналах, и не превращает полностью отсутствующие продажи в подтверждённый ноль.
- При известном ассортименте база блюда начинается с запуска, включая дни до первой продажи. Например: запуск 5 числа, первая продажа 7 числа — база начинается 5 числа. Если продаж нет во всей истории, блюдо в данном сочетании считается отсутствующим в ассортименте.
- Календарный фильтр не меняет определение ассортимента. Окно первых 7/14/28 дней отсчитывается отдельно для каждого блюда от его даты запуска и пересекается с календарным периодом.
- Продажи новинок до даты запуска исключаются из показателей запусков и рейтинга; известные продажи сохраняются отдельно для описательной динамики полных групп. Блюда, не имеющие продаж во всём файле, скрываются. Будущие запуски до выбранной конечной даты не показываются.
- «Зал», «Летняя терраса» и «Без Тарелок» объединяются в канал «Зал» и в продажах, и в заказах.

Ранее сохранённые наборы без списка запусков сохраняют прежний расчёт по продажам; при открытии такой структуры новым интерфейсом видна подсказка загрузить Excel с «Рестораны_Блюдо». Новые загрузки без листа не принимаются.

## СКП

СКП = количество проданных штук / подходящее количество заказов × 100.

Для отдельного блюда используем заказы его ресторанов/каналов, где оно входит в ассортимент, с даты его запуска и в выбранном окне. Для нескольких блюд строим **объединение** подходящих записей ресторан/канал/дата: каждая запись заказов учитывается один раз.

Итоговый СКП не равен сумме СКП блюд с разными базами и датами запуска. Дневные и итоговые СКП также рассчитываются из продаж и соответствующей базы, а не усреднением уже рассчитанных СКП.

Пропуск необходимых заказов не должен незаметно превращаться в ноль. В текущей реализации обнаруженные сочетания с продажами без заказов помечаются в `missingOrderSales`; затронутые показатели СКП имеют значение null и выводится пояснение. После загрузки исправленной выгрузки показатели пересчитываются.

Ноль — известный ассортимент и подходящая база, но отсутствие продаж за период. Пустая ячейка — отсутствующий ассортимент либо база. В основных числовых итогах значение null может обозначаться «—».

## Рейтинг с весами ассортимента

Цель — сравнить продажи нового и сезонного меню внутри соответствующих групп, учитывая различия в ассортименте и каналах. Это описание текущих результатов, а не оценка причинного прироста спроса относительно периода до запуска.

### Веса остальной сети

Для каждой группы, канала и периода конкретного блюда модель оценивает положительные относительные веса популярности по обычным блюдам, новинкам и сезонным блюдам группы в остальных ресторанах. Оцениваемый ресторан полностью исключён из оценки своих весов.

Используется модель выбора из доступного ассортимента: вероятность выбора блюда пропорциональна его весу внутри доступного набора. Веса подбираются по наблюдаемым продажам. Каждый ресторан в базе даёт одинаковый суммарный вклад, независимо от его объёма продаж группы. Разные наборы ассортимента связываются через общие блюда. Ресторан без данного канала не вносит в этот канал искусственную нулевую продажу.

Ассортимент обычных блюд берётся по положительным продажам всей истории; у новинок в разрешённых для запуска ресторанах дополнительно учитывается дата запуска. В остальных ресторанах то же блюдо может выступать обычной альтернативой группы и участвовать в оценке его веса. Блюдо, доступное в базе, но не проданное в выбранном периоде, может иметь нулевой вес. Отсутствующий вес отличается от нулевого.

### Общая часть ассортимента

Для каждого оцениваемого блюда берём доступные в целевом ресторане альтернативы, чей вес сопоставим с весом этого блюда по остальной сети. Локальные альтернативы без сопоставимого веса **исключаются одновременно из суммы весов и из количества продаж группы для ожидания**. Продажи оцениваемых новинок и общие продажи сохраняются в своих обычных таблицах.

Ожидание за день = продажи сопоставимой части группы × вес оцениваемого блюда / сумму весов сопоставимых доступных блюд группы.

За выбранные дни, блюда и каналы ожидания суммируются. В знаменатель нельзя включать неизвестный вес с произвольным нулём или средним и одновременно оставлять продажи такого блюда в базе группы.

Если в конкретном канале нет веса новинки, сопоставимых обычных блюд или устойчивой базы модели, соответствующая часть остаётся вне сравнения. Это не блокирует пригодные сочетания того же ресторана. Отрицательные продажи в дневной группе требуют отдельной обработки; текущая модель такие дни не оценивает и показывает причину.

### Факт, ожидание и охват

- «Продано, шт.» — все продажи выбранного меню.
- «Факт в сравнении, шт.» — фактические продажи той же части, для которой рассчитано ожидание.
- Охват — доля положительных продаж новинок, вошедших в сравнение. При полном охвате факты совпадают.
- Отклонение = (факт в сравнении / ожидание − 1) × 100%. Формат: +20%, −20%, 0%.
- При полном отсутствии сопоставимой базы или нулевом ожидании процентное отклонение не рассчитывается. Сравнение ресторанов с различным охватом требует учитывать состав оцененных продаж.
- «СКП факт в сравнении» и «Ожидаемый СКП» используют одну объединённую базу заказов по сравниваемым блюдам, каналам и дням, с учётом запуска и дней до первой продажи.
- Фильтр ресторанов ограничивает выводимые строки, но база весов включает всю остальную сеть. Даты, каналы и окно запуска влияют на расчёт весов. Фильтры типов и отдельных блюд ограничивают оцениваемые новинки; обычные альтернативы их групп остаются в базе.
- Отклонения ресторанов не обязаны суммироваться в ноль.

Клик по «Ожидаемо, шт.» раскрывает расчёт: группу и канал, полный и сравниваемый факт, продажи сопоставимой базы группы, ожидаемую долю и количество, число ресторанов/блюд в базе и список исключённых альтернатив. Продажи базы группы повторяются в строках её новинок; складывать их между новинками нельзя.

## Прежний расчёт по СКП

Дополнительный режим «По СКП остальной сети» сохраняется для сравнения. По каждому блюду и каналу берётся среднее арифметическое индивидуальных СКП остальных ресторанов с известным ассортиментом и подходящей базой. Рестораны имеют равный вес; нули выбранного периода при известном ассортименте учитываются. Среднее умножается на базу целевого ресторана / 100. Ожидания суммируются по его ассортименту. При недостающем сравнении отдельных сочетаний прежний режим не выводит частичную оценку всего меню.

## С учётом СКП до запуска — третий режим

«С учётом СКП до запуска» — режим по умолчанию при открытии демонстрационного отчёта, новой загрузке и сбросе фильтров. Ранее сохранённый явно выбранный режим восстанавливается из HTML. Два прежних режима можно выбрать в общем отчёте; они используют только основные массивы и сохраняют свои формулы. Показатель — описательный ориентир с учётом исходного уровня группы и динамики сети.

### История и сопоставимость

Дополнительные листы продаж и чеков «до» хранятся в `history`, отдельно от основных продаж, заказов, ассортимента и календарных фильтров. Их отсутствие не мешает прежним режимам. История обычного блюда только до запуска не делает его доступным после. Коды и псевдонимы СПР, нормализация каналов, ресторанов, групп и названий применяются к обоим источникам; приблизительное сопоставление названий не используется.

Для блюда с запуском L базовый период B всегда равен [L − 14 дней; L − 1 день], включая границы. Он не сдвигается с календарным фильтром. Для запуска 05.05 это 21.04–04.05, для запуска 19.05 — 05.05–18.05. Последняя база может целиком браться из основных листов; блюда предыдущего запуска в ней допустимы. Продажи блюда до собственного запуска исключаются и диагностируются.

База берётся из объединённой истории по фактическим датам. Правило запуска зависит от ресторана: продажи блюда СПР до старта исключаются только в ресторанах, где оно указано как запуск; вне списка они остаются обычными продажами группы в истории. Внутри листа строки агрегируются штатно. Совпадающие агрегаты на пересечении двух источников учитываются один раз; конфликтующие сочетания блюдо/ресторан/канал/дата либо ресторан/канал/дата заказов исключают затронутую базу с отдельной причиной. Они не меняют основные массивы прежних режимов.

Источники продаж и заказов должны глобально покрывать все 14 календарных дней B. Отдельному ресторану/каналу не требуются 14 ненулевых дней заказов: канал может работать нерегулярно. При известном источнике группы заказ без продажи группы в этот день означает нулевую продажу. Полное отсутствие группы за B во всех источниках означает «Нет данных группы до запуска», а не нулевой СКП. Продажи без подходящей записи заказов, конфликты, неполный период, нулевая база и отрицательные количества имеют отдельные причины.

### Собственный уровень и динамика сети

Период T пересекает выбранные даты, запуск конкретного блюда и его окно первых 7/14/28 дней. Веса и связанные компоненты берутся из неизменённой модели ассортимента по группе/каналу/T, с исключением целевого ресторана r.

Для каждого ресторана u набор C_u содержит его ассортимент из основных источников с запуском не позже конца T и сопоставимыми весами: известный вес, связанный с оцениваемым блюдом компонент для положительных весов, корректная обработка известного нулевого веса. Нужна хотя бы одна обычная альтернатива с положительным сопоставимым весом. Количества до и после берутся только по C_u, с соблюдением запусков. Локальные альтернативы, несвязанные блюда и блюда только в истории до исключаются из этих количеств и перечисляются в детализации.

СКП группы до для ресторана r: `R_before = 100 × Q_before(C_r) / N_before`, где N_before — все его заказы в нужном канале за B. Дневные СКП не усредняются. При нулевом или отрицательном Q_before относительное ожидание не вычисляется.

Охват базы до: положительные продажи C_r за B / все положительные продажи группы r/канал за B × 100%. Низкий охват остаётся видимым; это граница оценки сопоставимой части группы.

Для динамики выбирается один набор P остальных ресторанов с корректной базой B и T, действующим каналом, сопоставимыми обычными альтернативами и положительным СКП до. Неполные чеки, конфликт источников или отрицательные дневные количества исключают пару из обеих половин среднего. Известный ноль после при подходящих заказах участвует как нулевой СКП после.

`M_before = среднее R_u_before по P`; `M_after = среднее R_u_after по тому же P`; `K = M_after / M_before`.

Это отношение двух средних, а не среднее индивидуальных отношений и не отношение сетевых сумм. Каждый ресторан имеет равный вклад. При пустом P K неизвестен, значение 1 не подставляется. При K = 0 ожидание равно нулю, процент для нулевого итогового ожидания отсутствует. Число ресторанов для K выводится отдельно от числа ресторанов модели весов; оценка по одному ресторану сопровождается предупреждением. Фильтр ресторанов ограничивает вывод, сохраняя остальную сеть для обоих расчётов. Для разных T коэффициент пересчитывается.

### Ожидание, факт и вывод

В день t доступный набор A_r,t — часть C_r, уже запущенная к этому дню. `p_i,t = w_i / сумма весов A_r,t`.

`Ожидание_i,r,канал,t = N_r,канал,t / 100 × R_r_before × K × p_i,t`.

Доли меняются в день следующего запуска. Подходящие заказы в дни с нулём продаж новинки учитываются. Промежуточные значения не округляются. Продажи целевого ресторана после используются для факта и диагностики, но не для его весов, K или непосредственного расчёта ожидаемых штук.

Ожидания суммируются по дням, блюдам и каналам. Факт в сравнении берётся по тем же подходящим сочетаниям. Итоговое отклонение равно `(сумма факта в сравнении / сумма ожиданий − 1) × 100%`. Фактический и ожидаемый СКП используют одно объединение записей заказов, без дублирования между блюдами. Отсутствующая база одной группы исключает только её часть; полные продажи меню остаются отдельным показателем.

Охват рейтинга — положительные продажи новинок, вошедшие в сравнение, / все положительные продажи выбранных новинок × 100%. Он отличается от охвата базы до. Если база отсутствует полностью, ожидание неизвестно и причины доступны по клику.

Детализация хранит отдельные B и T по блюду/каналу, СКП и охват базы до, исключённые блюда/дни, два средних СКП сети, K, два числа ресторанов, ожидаемую долю и штуки. Ожидаемая доля взвешена по подходящим заказам: `сумма N_t × p_t / сумма N_t`. Числа заказов в интерфейсе, подсказках и CSV не показываются. CSV рейтинга содержит название режима, корректный факт в сравнении, ожидание, охват и пояснение. Сохранённый HTML сохраняет историю, выбранный режим и общие фильтры; публичный `index.html` содержит только искусственную демонстрацию.

Индексы истории и кеши расчётов привязаны к конкретному загруженному набору. Ключи сценариев включают версию модели, блюдо/запуск, B, T, канал и целевой ресторан. Новый импорт создаёт новый набор и не использует прежние кеши.

## Интерфейс и обновление

В начале «Обзора» расположен автоматический блок «Итоги по сети». Он разделяет суммарный результат выбранных блюд относительно ожидания действующей модели и изменение фактического СКП полных групп до/после запуска с поправкой на структуру ресторанов и каналов ДО. Ожидания используются из существующего рейтинга; проценты ресторанов не усредняются. Полные группы включают локальные и снятые блюда, используют общий пригодный состав, единые знаменатели и аддитивные вклады. История не заменяется нулём, несколько запусков не складываются в общий эффект. Полная методика, охват и ограничения описаны в [NETWORK_SUMMARY.md](NETWORK_SUMMARY.md).

- Четыре вкладки: Обзор, Блюда, Рестораны, Каналы.
- Общие фильтры; Ресторан и Канал рядом, Группа и Блюдо рядом. Ресторанный фильтр доступен и в карточке блюда.
- В карточке блюда нет отдельного выбора метода рейтинга: её рейтинги используют метод общего отчёта.
- Количество заказов нигде не показывается, включая CSV и подсказки. Подпись «СКП на 100 заказов» разрешена.
- Обзор содержит таблицу блюдо × дата с переключением штуки/СКП. Даты краткие, например 5.май. Мягкая красно-жёлто-зелёная шкала.
- В обзоре заголовки дат и «Итого» сортируют все блюда по выбранному показателю: первый щелчок — убывание, следующий — возрастание; пустые значения остаются внизу. При такой сортировке дата запуска подписана у блюда, общая строка итогов остаётся на месте. «По запускам» возвращает группировку по датам запуска. CSV повторяет порядок таблицы, сохранённый HTML восстанавливает сортировку и показатель.
- Строки блюд без данных выбранных ресторанов, каналов и периода скрыты. Подтверждённый ассортимент с подходящей базой и нулевыми продажами остаётся видимым; ноль не считается отсутствием данных.
- Сравнение запусков стоит под дневной таблицей и отображается только при наличии более одного запуска с данными; иначе блок полностью убирается. Подписи осей графиков — целые числа.
- В таблицах доступны все строки с прокруткой; первый столбец влево, остальные данные и заголовки по центру. Контент использует доступную ширину экрана.
- Рейтинг скрывает рестораны с нулевыми продажами меню. Матрица скрывает рестораны, где выбранных блюд нет в ассортименте.
- В матрице ресторан × блюдо есть итоговые строка и столбец. Блюда идут от ранних запусков к поздним, внутри запуска — по убыванию продаж. Общий СКП матрицы рассчитывается по объединённой базе.
- В таблице блюд по каналам есть переключение штуки/СКП, и итог соответствует выбранному показателю.
- Загрузка Excel полностью заменяет справочник и данные. Веса и ассортимент пересчитываются по новой истории.
- Браузер работает локально. Сохранённый рабочий HTML содержит загруженные данные и не предназначен для публичного Git-репозитория.
