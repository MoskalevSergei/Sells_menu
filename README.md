# Sells_menu

Готовый проект для продолжения работы над дашбордом продаж нового меню в Codex.

`index.html` — уже собранный дашборд. Его можно открыть двойным щелчком без сервера и без интернета. В нём искусственные данные; в заголовке это обозначено явно. Для работы со своими данными нажмите **«Загрузить Excel»** и выберите файл `.xlsx`, содержащий `Меню_Продажи` в названии. После загрузки кнопка **«Сохранить с данными»** создаёт отдельный рабочий HTML.

Для новых загрузок обязателен лист **«Рестораны_Блюдо»** со столбцами `Код` и `Ресторан`, а в «СПР» — столбец `Код`. Показатели запусков учитывают только пары из списка и блюда из СПР. Каждый код СПР должен быть в списке хотя бы для одного ресторана; иначе загрузка покажет ошибку. Продажи вне разрешённых пар остаются обычными продажами для базы групп. Список запусков сохраняется вместе с данными в рабочем HTML.

Разделы «Обзор», «Блюда», «Рестораны» и «Каналы» находятся в компактном меню слева. Кнопка **«Фильтры»** открывает панель поверх отчёта; изменения применяются сразу, а **«Показать отчёт»**, Escape или щелчок вне панели закрывают её. Выбранные ограничения видны над отчётом и сохраняются при переключении разделов. Кнопка **«Сбросить»** возвращает общий период, весь ассортимент и исходную модель рейтинга.

В рейтинге доступны три режима: **«С учётом СКП до запуска» (по умолчанию)**, «С весами ассортимента» и «По СКП остальной сети». Режим до запуска использует собственный уровень сопоставимой группы за 14 дней до старта, динамику остальных ресторанов и текущие веса блюд. История читается из необязательных листов «до» и подходящих дат основных листов; её отсутствие не меняет формулы других режимов. По клику на ожидание видны периоды, состав базы, коэффициент сети и охват. Карточка блюда использует общий метод рейтинга и не содержит отдельного переключателя. Сохранённый HTML удерживает данные истории, выбранный режим и общие фильтры. Искусственный пример содержит историю до запуска; подробности — в `docs/BUSINESS_RULES.md` и `docs/EXCEL_FORMAT.md`.

В «Обзоре» нажмите заголовок даты или **«Итого»** для сортировки блюд по убыванию; повторное нажатие меняет направление. Кнопка **«По запускам»** возвращает группировку. Блюда без данных выбранных ресторанов, каналов и периода скрываются; подтверждённые нулевые продажи остаются. Сортировка и показатель штуки/СКП сохраняются в рабочем HTML.

В начале «Обзора» блок **«Итоги по сети»** автоматически формирует вывод и отдельные карточки нового и сезонного меню. Он различает результат блюд относительно ожидания выбранной модели и динамику полных групп до/после запуска. Для групп видны фактические СКП, показатель при структуре ресторанов и каналов ДО, охват, периоды и основные вклады. Фильтры ограничивают вывод, а при выборе части ресторанов заголовок меняется на «По выбранным ресторанам». Текст создаётся локально и сохраняется в рабочем HTML. Подробности — [методика итогов по сети](docs/NETWORK_SUMMARY.md).

## Загрузка в Sells_menu

1. Распакуйте архив и откройте папку `Sells_menu`, в которой находятся `index.html` и `AGENTS.md`.
2. Откройте [MoskalevSergei/Sells_menu](https://github.com/MoskalevSergei/Sells_menu). Выберите загрузку файлов: **Add file → Upload files**; в пустом репозитории может отображаться ссылка **uploading an existing file**.
3. Перетащите **содержимое** папки: файлы и вложенные папки. `AGENTS.md` должен оказаться в корне репозитория, а не внутри ещё одной папки `Sells_menu`.
4. Сохраните загрузку через **Commit changes**. Архив ZIP загружать как единственный файл не нужно: Codex нужны распакованные исходники.
5. Откройте Codex, выберите репозиторий `Sells_menu` и вставьте задание из `START_CODEX.md`.

В комплект включены только демонстрационные данные. Рабочие выгрузки и рабочий HTML с реальными данными храните отдельно от этого репозитория.

## Для Codex и разработчика

Нужны **Node.js 20+** и **Python 3**. Python используется только в адаптере XML для тестирования загрузки Excel. Дополнительные пакеты устанавливать не требуется.

```bash
npm run check
```

Команда собирает `index.html` и запускает проверки. Для подготовки среды с полем setup script можно использовать:

```bash
bash scripts/codex-setup.sh
```

Другие команды:

| Команда | Назначение |
|---|---|
| `npm run build` | Пересобрать дашборд из исходников с демонстрационными данными |
| `npm test` | Проверить расчёты, загрузку XLSX и генерацию интерфейса |
| `npm start` | Открыть локальный сервер на `http://127.0.0.1:3000` |
| `npm run example` | Создать искусственный Excel `examples/Меню_Продажи_пример.xlsx` для проверки загрузки |

## Что где находится

| Файл или папка | Содержимое |
|---|---|
| `index.html` | Готовый HTML для открытия в браузере |
| `AGENTS.md` | Постоянные инструкции для Codex |
| `START_CODEX.md` | Первое задание для вставки в Codex |
| `src/engine.js` | Чтение Excel, расчёты СКП и рейтинга |
| `src/app.js` | Фильтры, вкладки, таблицы, CSV и сохранение HTML |
| `src/template.html` | Разметка и оформление |
| `scripts/` | Сборка, искусственные данные, пример Excel, локальный сервер |
| `tests/` | Контрольные примеры и проверка импорта/интерфейса |
| `docs/BUSINESS_RULES.md` | Утверждённая методика и требования |
| `docs/EXCEL_FORMAT.md` | Листы и столбцы входного файла |
| `vendor/` | Встроенная библиотека JSZip и её лицензия |

Сборка воспроизводима и не использует машинных путей из предыдущей рабочей среды. В репозиторий нужно добавлять исходники вместе с собранным `index.html`.

Официальная документация: [инструкции AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [настройка облачной среды](https://learn.chatgpt.com/docs/environments/cloud-environment).
